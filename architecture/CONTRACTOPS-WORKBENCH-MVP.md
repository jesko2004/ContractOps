# ContractOps 第 5–8 项：知识问答、合同预审与人工审批 MVP

更新：2026-10-09。用途是本地演示和面试讲解，不是生产部署验收。

## 核心闭环

资料上传 → PDF Inspector / DOCX 解析 → 知识库保存版本和来源 → 合同台账关联已有资料 → 人工核对候选 → 生成带依据的预审 → 人工领取审批 → 通过、驳回或退回修改。

PDF Inspector 是文档处理引擎，ContractOps 是业务事实源。模型只帮助阅读，不能执行写操作、批准合同或创建履约义务。

## 已完成的四个模块

| 项目 | 页面与后端能力 | 边界 |
| --- | --- | --- |
| 5. 知识问答 | 全部可访问资料 / 指定库 / 单文档范围；当前页面最多保留 6 轮；每轮重新鉴权检索；固定版本、片段和来源页引用 | 默认原文检索；配置兼容模型后才启用 RAG，不是向量检索 |
| 6. 合同工作台 | 名称、对方、金额币种、有效期、当前版本、审批状态；关联已有合同资料；金额/日期规则候选人工核对；原文和最近两版本差异 | 候选核对只保存标记，不自动改写台账；版本 Diff 是片段摘要差异，不是逐字修订模式 |
| 7. 预审助手 | 台账摘要、确定性缺项、待核对事项；付款金额、交付期限、违约终止主题的合同/制度原文并列；可选模型语义建议 | 关键词配对不等于制度适用或违规判断；未启用模型时明确显示“未生成模型建议” |
| 8. 审批中心 | 我的待办、我的已办、可访问审批过程；领取任务、通过/驳回/退回修改、自然语言意见；状态和审批记录同步 | 最终决定由人做；本地身份切换仅为演示，不是企业账号系统 |

## 本地演示步骤

1. 按 [知识库指南](CONTRACTOPS-KNOWLEDGE-MVP.md) 启动并连接 `http://127.0.0.1:8081`。已有数据库增量扩展，不删除原件或历史版本。
2. 经办人新建知识库，分别上传“合同资料”和“公司制度”，等待解析完成。PDF Inspector 的接入方法沿用原指南。
3. 在知识问答页选择库或文档，提问并打开引用原文；换范围或身份会清空当前会话。
4. 在合同管理页创建台账，选择已经入库的合同资料，不需要重复上传原件。
5. 打开金额/日期候选的来源，人工勾选并保存。规则可能漏识别或误识别，未识别不代表原文没有该字段。
6. 选择参考制度所在知识库，生成预审。展开主题原文，确认合同和制度来源；没有制度正文时明确提示依据不足。
7. 提交人工审批，顶部切换为“审批人”，到审批中心领取待办，核对预审与原文，填写意见并操作。
8. 在已办记录和合同详情查看结果。修改资料版本后，旧报告显示失效；重新关联合同修订版后，可对比最近两个版本并重新生成报告。

本地启动时创建一条默认“本地人工法务核查”顺序审批策略，不生成合同、文档或审批实例。可配置顺序策略的后端接口沿用现有服务；没有增加可视化流程编排、并行会签或自动审批。

## 可选真实模型配置

默认不开启模型，没有配置就只显示原文检索和规则预审。启动进程前设置环境变量，例如本机兼容服务：

```powershell
$env:CONTRACTOPS_KNOWLEDGE_MODEL_ENABLED='true'
$env:CONTRACTOPS_MODEL_BASE_URL='http://127.0.0.1:4000/v1'
$env:CONTRACTOPS_DOCUMENT_MODEL_NAME='你的服务实际提供的模型名'
# 仅在服务要求时设置后端 API 密钥，不要提交到 Git。
$env:CONTRACTOPS_KNOWLEDGE_MODEL_API_KEY=''
$env:CONTRACTOPS_KNOWLEDGE_MODEL_TIMEOUT_SECONDS='15'
& .\services\contract-api\.venv\Scripts\python.exe .\services\contract-api\scripts\knowledge_demo.py
```

远程地址必须为 HTTPS，本机回环地址可以 HTTP；配置是后端运维能力，不接受用户任意指定请求地址，禁止重定向。模型服务必须兼容 `/chat/completions` 和 JSON 对象输出；不支持时自动降级。JSON 模式不保证业务结构，因此应用还会独立验证字段、数量、引用编号和逐字引用。[协议参考](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)

提示词将文档、问题和历史问题作为不可信数据，只允许依据本次授权片段回答。模型没有工具调用或业务写接口；引用不合法、结果截断、超时或远端失败时，退回原文检索 / 规则报告。页面明确显示实际模式。

引用校验仅证明所引文字确实存在，不证明结论被文字充分支持，仍需人工判断。当前机器未配置真实模型服务；本轮验证的是本地 HTTP 测试服务的协议、成功分支和故障降级，不能声称已通过真实模型效果评测。

## 后端设计与一致性

- SQLite 本地业务适配器实现原有 `ContractService`、`ApprovalService` 接口，复用状态机与角色规则；同一数据库保存知识资料、合同关联、预审及审批。
- 关联资料固定到不可变的知识文档版本，只创建业务版本引用，不复制上传原件；查看、引用和 Diff 均通过知识资料接口重新鉴权。
- 合同写入、审批任务领取和决定使用版本检查；本地事务采用 `BEGIN IMMEDIATE`。审批步骤和合同终态在同一事务内更新，保存人工意见及本地操作记录。
- 核心创建、关联、提交、领取、决定支持持久化幂等重试。候选核对相同结果可重放；生成预审目前是每次生成一个新报告，不提供严格的同键单次生成保证。
- 报告绑定合同业务版本、关联文档摘要/状态、人工核对快照、台账字段和所选库的当前制度版本。重新读取时计算指纹；生成期间变化则拒绝保存结果，生成后变化则标记 `STALE`。
- 提交与通过前检查当前报告；已有管理资料关联时，直接调用原审批接口也会检查。旧报告失效仍允许驳回或退回修改。已经保存的审批结果不因后续制度变化而被重写。
- 这是请求级版本防护，不是横跨制度更新和审批事务的严格串行化保证；更强的并发一致性需要数据库锁/快照协议与真实并发集成测试。

新增接口以 `/v1/workspace` 为前缀：`GET /contracts`、`GET /contracts/{id}`、`POST /contracts/{id}/documents`、`POST /contracts/{id}:confirm`、`POST /contracts/{id}/reviews`、`GET /contracts/{id}/review`、`POST /contracts/{id}:submit`、`GET /contracts/{id}/diff`、`GET /approval-history?handled=true`。领取和决定沿用 `/v1/approval-steps/{id}:claim` / `:decide`。

正式应用保留原有 JWT/PostgreSQL 入口，不会自动退回 SQLite。新增持久化表 `workspace_contract_documents` 和 `workspace_review_reports` 需迁移 `20261009_0011` 与更新 runtime grants；开启并强制租户 RLS，报告只授予 API 插入和读取权限。

## 验证与明确限制

本轮本机验收：Ruff 通过，mypy 检查 76 个源文件通过；完整 pytest **175 passed / 23 skipped**。两个页面脚本均通过，并检查了桌面/手机截图。新增 SQLite 并发领取测试验证同一版本仅一个请求成功；这是本地适配器验证，不替代 PostgreSQL 集成。

- 后端质量检查覆盖问答作用域、引用校验、模型故障、数据持久化、关联重试、版本 Diff、三种人工决定、过期报告阻止通过、直接接口防绕过和历史读取。
- `scripts/check_knowledge_ui.cjs` 回归知识库 1–4 项；`scripts/check_workbench_ui.cjs` 验收 5–8 的页面闭环，包括角色切换、已办意见和桌面/手机布局。测试使用独立可丢弃的 SQLite 数据库，不向用户知识库写验收资料。
- 业务 UI 脚本需设置 `WORKBENCH_UI_DISPOSABLE=yes`、测试服务的 `CONTRACTOPS_LOCAL_TOKEN`、可选 `PLAYWRIGHT_MODULE` / `KNOWLEDGE_UI_BROWSER`，默认只请求本机 8082。
- 当前源选择器最多展示 100 条当前可访问文档；合同台账每页 30 条；审批历史最近 100 条，详情按合同过滤后截取。适合小规模演示，不是海量知识库管理。
- SQLite 本地身份、操作记录不等同正式账号隔离、PostgreSQL RLS 或防篡改审计。新增 PG 关联路径不保证现有审计 Outbox 全覆盖；关联的业务版本引用不走原 MinIO 文档 Worker。
- 本机没有 PostgreSQL/Redis，真实迁移升级回滚、RLS 和新增 PG 业务路径尚未实测；相关跳过用例不能计为通过。
- 不包含 OCR 实际启用、向量检索/重排序、正式权限管理 UI、转办 UI、本地转办实现、履约义务自动创建或生产发布。Inspector 仍仅直接接入管理知识资料。

# ContractOps 项目边界

## 一句话定位

ContractOps 是面向企业法务、财务、采购和业务团队的合同审批与履约风控后端服务，
负责合同台账、不可变版本、审批策略、审批待办、履约义务、风险事件、提醒和审计。

系统可以通过规则、文档解析和模型生成辅助信息，但合同审批、义务确认和风险处置都
必须由有权限的人员完成。

## 与 PDF Inspector 的边界

ContractOps 不以通用 PDF 检查、版面分析或文档问答为产品目标。PDF/DOCX 解析只负责
把合同原文转换成可引用的正文、页码和条款证据，属于文档处理适配器。

项目的主要工程深度来自企业业务服务：多租户数据隔离、审批状态机、条件审批策略、
履约义务台账、可靠异步事件、到期调度、风险升级和不可抵赖审计。

## MVP 业务闭环

1. 合同经办人创建合同台账并上传不可变文件版本。
2. 经办人填写合同金额、交易对手、有效期和业务归属等结构化字段。
3. 系统按照合同类型、金额和风险标签选择审批策略并生成审批实例。
4. 法务、财务和业务角色处理个人待办，可以通过、驳回、退回修改或转交。
5. 所有审批完成后，授权人员确认合同生效并登记付款、交付、验收和续约义务。
6. 调度器领取即将到期或已经逾期的义务，生成风险事件并发送去重提醒。
7. 风险负责人确认、延期、关闭或升级风险事件，系统保留完整操作记录。
8. 合同修订通过新版本和新审批实例完成，旧版本、旧决定和旧义务保持可追溯。

## 核心能力

### 合同台账与版本

- 合同主体、金额、币种、期限、归属部门和负责人；
- 文件版本不可覆盖，当前版本通过显式切换更新；
- 内容哈希、重复上传校验和合同版本 Diff；
- 合同生命周期与文件处理状态分离。

### 审批工作流

- 审批策略按合同类型、金额、部门和风险标签匹配；
- 首版支持顺序审批和条件跳过，后续增加并行会签；
- 审批实例保存策略快照，策略变更不影响进行中的流程；
- 待办领取、通过、驳回、退回、转交和超时升级；
- `Idempotency-Key`、乐观锁和唯一约束防止重复决定。

### 履约与风险事件

- 付款、交付、验收、开票、续约和终止通知等义务；
- 义务负责人、计划时间、宽限期、证据和完成状态；
- 即将到期、逾期、金额异常和缺少证据等风险事件；
- 数据库租约领取任务，提醒去重，失败重试和逾期升级；
- 合同暂停、终止或替换后同步停止无效任务。

### 企业级后端保障

- JWT 租户上下文、RBAC、部门数据范围和 PostgreSQL RLS；
- Transactional Outbox、Redis Streams、消费者幂等和死信处理；
- 操作审计、业务审计和安全审计分级存储；
- OpenTelemetry 链路、Prometheus 指标和结构化日志；
- API 契约测试、数据库集成测试、故障恢复测试和压测。

## 辅助智能能力

以下能力在审批和履约主链路稳定后实现：

- PDF/DOCX 正文、页码和标题层级解析；
- 条款分类、金额日期提取和原文证据定位；
- 基于规则与模型的风险提示；
- 履约义务候选项生成；
- 合同版本条款级 Diff。

模型输出只能形成待确认草稿或风险提示，不能直接通过审批、激活合同、完成义务或关闭
风险事件。

## 当前已经建立

- `services/contract-api` FastAPI 应用骨架；
- `/health/live`、`/health/ready`、`/v1/system/info`；
- 请求 ID 生成与回传；
- 初版审查状态机及单元测试；
- PostgreSQL/pgvector 初始迁移；
- PostgreSQL、Redis、MinIO、API 的独立本地 Compose；
- JWT 租户上下文、RBAC、部门/本人/租户三级数据范围；
- Contract、ContractVersion PostgreSQL Repository 和事务级 RLS 上下文；
- 合同创建、查询、不可变版本登记及租户级幂等；
- 多租户隔离、重复请求和版本不可覆盖集成测试；
- 项目范围、实施计划和验收边界。

## 尚未实现

- ApprovalPolicy、ApprovalInstance、ApprovalStep 和待办 API；
- Outbox Publisher、Redis Streams Worker 和死信管理；
- Obligation、RiskEvent、数据库租约和提醒去重；
- 文件上传、PDF/DOCX 解析和条款证据；
- 模型辅助提取和风险提示；
- 对象存储直传、OpenTelemetry、指标看板、完整端到端测试与压测。

## 明确不做

- 通用 PDF Inspector 或文档质量检查器；
- 通用企业知识库和文档问答平台；
- 合同在线协同编辑器；
- 电子签章、支付和电子发票平台；
- 自动给出最终法律意见或自动批准合同；
- ERP、OA、钉钉和飞书的全量集成；
- 第一阶段引入 Kafka、OpenSearch、Kubernetes 或复杂多 Agent；
- 同时支持大量模型供应商。

## 成功标准

项目完成时必须能演示：两个租户的数据隔离、合同版本不可覆盖、审批策略匹配、三角色
审批、重复请求不产生重复决定、履约任务在服务重启后恢复、同一提醒不会重复发送、风险
事件可以升级和关闭、关键操作形成完整审计链。

文档解析演示必须提供页码和原文证据，但它不作为项目成立的前提。所有性能、稳定性和
质量数字必须来自仓库内可复现的测试或报告。

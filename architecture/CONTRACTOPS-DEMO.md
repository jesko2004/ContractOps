# ContractOps 最终演示脚本

## 演示目标

在 15 分钟内证明 ContractOps 是企业合同审批与履约风控后端服务，而不是通用 PDF
检查器：核心证据是租户隔离、可并发审批、可靠事件、履约调度、可追踪审计、文档证据和
故障恢复。

## 演示前准备

```bash
docker compose -f deploy/contractops/docker-compose.yml --profile observability up -d --build
```

准备租户 A 的经办人、法务、财务和审计员令牌，以及租户 B 的经办人令牌。所有演示请求
固定携带 `X-Request-ID`，写请求携带唯一 `Idempotency-Key`。

## 演示流程

1. **合同建档（2 分钟）**：租户 A 创建办公服务合同和不可变版本；重复发送同一幂等键，
   证明只生成一份资源。用租户 B 查询该合同，展示稳定的 404/403 与安全审计。
2. **条件审批（3 分钟）**：发布包含法务和高金额财务步骤的策略，提交合同。两个请求使用
   同一 `expected_version` 并发决定，展示只有一个成功，另一个返回版本冲突。
3. **可靠事件（2 分钟）**：按运行手册暂停 Redis，再完成一次业务操作；展示事务已提交、
   Outbox 未丢失。恢复 Redis 后，事件被发送且通知只有一次。
4. **履约风控（2 分钟）**：登记付款义务，把时间推进到逾期窗口；Scheduler 创建风险、
   提醒和升级记录。终止合同后，展示后续任务被取消。
5. **文档证据（2 分钟）**：上传 DOCX/PDF，展示页码或标题路径、金额/日期 Finding 和版本
   Diff。强调模型关闭时仍能运行，模型建议只能成为待人工确认的草稿。
6. **审计与观测（2 分钟）**：使用第 2 步的 request/trace ID 查询审批、Outbox、Worker、
   通知全链路；打开 Prometheus/Grafana，展示失败和安全拒绝指标。
7. **生产证据（2 分钟）**：打开 CI 的 `contractops-m7-evidence`，说明 QPS、P95、失败率、
   冲突正确率、恢复率、重复通知率和单合同数据库成本的测量条件。

## 必须展示的失败路径

- 跨租户读取被阻断；
- 重复写请求返回原结果；
- 并发审批的陈旧版本被拒绝；
- Redis/通知失败后任务可恢复；
- 恶意高压缩 DOCX 被拒绝；
- Webhook 私网地址和跳转被拒绝；
- 日志与审计不出现合同正文、JWT 和密钥。

## 结束口径

ContractOps 的最终判断仍由企业人员完成。模型只提供带原文位置的候选提示；审批、履约、
风险处置和审计都由确定性状态机、数据库约束和可恢复任务保证。
